# CI, Linting, and Browser Smoke Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every push and PR automatically runs the existing unit suite, an ESLint pass, and a Playwright smoke suite against a seeded local server, so regressions are caught before `flyctl deploy`.

**Architecture:** One GitHub Actions workflow (`.github/workflows/ci.yml`) with three independent jobs: `test`, `lint`, `e2e`. Lint is ESLint 9 flat config, with separate Node and browser globals. The e2e job boots the real Express app (`start()` from `src/server.js`) against a temporary SQLite database seeded with fixture documents. It blocks all upstream network access, so the browser tests are deterministic and never touch UBC Open Collections or Turso.

**Tech Stack:** GitHub Actions, Node 22 (matches `Dockerfile`: `node:22-bookworm-slim`), `node:test`, ESLint 9 + `@eslint/js` + `globals`, `@playwright/test` (Chromium only).

**Spec:** No separate spec doc. The requirements come from the 2026-10-20 CI audit conversation:
1. Add a CI workflow that runs `npm test` on PRs and pushes.
2. Add ESLint and a lint job.
3. Add Playwright smoke tests that load each tab, check that charts render and no console errors appear, and open a document modal.

## Global Constraints

- Node version in CI: `22.x` (production runtime is `node:22-bookworm-slim`; `package.json` engines `>=22.5`).
- New packages are **devDependencies only**. Runtime `dependencies` must not change.
- Tests must never touch `./data/metrics.sqlite` (iCloud lock hang; see `scripts/run-tests.mjs`). Every test or e2e process uses a fresh temp data dir.
- e2e must make **zero** outbound network calls: `TURSO_DATABASE_URL=''`, `UBC_API_BASE_URL=http://127.0.0.1:9`, `SKIP_LOCAL_ENV=1` (so `.env` is never loaded).
- Workflow permissions: `contents: read` only (match `gitleaks.yml`).
- CI triggers: `pull_request`, and `push` to `main` and `v2`.
- Commit messages follow the repo's conventional style (`ci:`, `chore(lint):`, `test(e2e):`).

## Review Focus

1. **CI runner missing system binaries.** `test/pdfParser.test.js` shells out to `pdftotext`, and `test/topicLabelQuality.test.js` runs `python3` (stdlib only). The `test` job must install `poppler-utils`, or those tests fail on CI while passing locally. This is pinned by Task 1 step 3: CI must run green on a clean runner.
2. **The e2e server leaks to the network or `.env`.** If `SKIP_LOCAL_ENV` is missing, a developer's `.env` (with a Turso URL) would point the e2e server at production. This is pinned by Task 4's `start-server.mjs` env block and by the "health endpoint and no outbound hosts" spec in Task 5.
3. **The startup concept rebuild spawns a worker during e2e.** `start()` launches a concept-rebuild child job when `data/concepts/status.json` has no `lastSuccessAt`. The seed calls `persistConceptArtifact()` so that never fires. This is pinned by the seed in Task 4 and verified in Task 4 step 4 (no "Concept rebuild job started" in the server log).
4. **Lint rules that flag intentional patterns.** Examples are `_`-prefixed unused args in Express error handlers (`(error, req, res, _next)`), empty `catch {}` blocks with comments, and `d3`/`Chart` browser globals. The config must accommodate these rather than litter the code with disables. This is pinned by Task 2 step 4 (zero errors on the current tree with the config, without disable comments).
5. **Flaky e2e from async rendering.** The tables fill after `fetch`, and charts render after the tab becomes active. Specs must wait on locators (`expect(...).toHaveCount`, `toBeVisible`), never fixed sleeps. This is pinned by the Task 5 specs, which use only web-first assertions, and by running the suite 3x with `--repeat-each=3` in Task 5 step 4.

- [ ] **Step 3: Write `e2e/fixtures.js`**

```js
import { test as base, expect } from '@playwright/test';

// Any uncaught page error or console.error fails the test. Upstream-only
// requests are aborted so a regression that reaches for the network shows up
// as a failed test, not a hang.
export const test = base.extend({
  page: async ({ page }, use) => {
    const problems = [];
    page.on('pageerror', (err) => problems.push(`pageerror: ${err.message}`));
    page.on('console', (msg) => {
      if (msg.type() === 'error') problems.push(`console.error: ${msg.text()}`);
    });
    await page.route(/^https?:\/\/(?!127\.0\.0\.1|localhost)/, (route) => {
      problems.push(`external request: ${route.request().url()}`);
      return route.abort();
    });
    await use(page);
    expect(problems, 'browser errors during test').toEqual([]);
  },
});

export { expect };
```
